# lamp_detection_example

Демо-приложение пакета [`lamp_detection`](../README.md). Показывает весь пайплайн на
реальном железе: превью камеры, перетаскиваемые ROI, калибровка, Live-детекция двух
сигнальных ламп, журнал событий со статусами доставки, панель диагностики и график
`whiteScore` / `redScore`.

Приложение использует **только публичный API** пакета — импортируется
`package:lamp_detection/lamp_detection.dart`, `src/**` не трогается.

## Запуск

```
cd example
flutter pub get
flutter run
```

Пакет подключается по относительному пути (`lamp_detection: path: ../` в
`example/pubspec.yaml`), так что в `pubspec.yaml` пакета ничего менять не нужно.

## Разрешения

Уже прописаны в `example/`, ничего добавлять не требуется.

**Android** — `android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.CAMERA"/>
<uses-feature android:name="android.hardware.camera" android:required="true"/>
```

**iOS** — `ios/Runner/Info.plist`:

```xml
<key>NSCameraUsageDescription</key>
<string>Камера нужна, чтобы видеть сигнальные лампы белой и красной и считать попадания.</string>
```

Плагин `camera` сам запрашивает разрешение при первом `CameraController.initialize()`;
если пользователь отказал, `session.errors` получит сообщение, приложение не упадёт.

## Что на экране

Сверху вниз:

1. **Кнопки управления** (`Wrap`):
   - `Start` / `Stop` — запуск и полная остановка камеры;
   - `Калибровка (обе выключены)` — набирает `LampConfig.calibrationFrames` кадров
     с погашенными лампами; на кнопке виден прогресс `N/30`;
   - `CSV: вкл / выкл` — запись признаков каждого кадра в файл в приватном каталоге;
   - `Новая сессия` — новый `sessionId`, счётчики и история событий обнуляются;
   - `Reset счётчиков` — сброс WHITE/RED HITS без смены сессии;
   - `Поворот ROI 90°` — ручная подстройка `FrameMapping`, если авто-расчёт по
     `sensorOrientation` не угадал ориентацию сенсора;
   - `Сеть: есть / нет` — переключает `MockHitEventSender.offline`, чтобы
     посмотреть, как pending-очередь копит события и разгребает их после
     `deliverPending()`.
2. **Превью + `RoiEditor`** — два прямоугольника (WHITE / RED), которые тянутся
   за центр (перемещение) и за угол (размер). Координаты нормализованы, ROI
   переживают поворот и смену разрешения. Отпускание пальца пишет ROI в
   `SettingsStore`.
3. **`_LampStatus`** — две плашки `WHITE ON/OFF` и `RED ON/OFF` (загораются в такт
   `LampEvaluation.whiteLit` / `redLit`) и счётчики попаданий.
4. **`ScoreChart`** — 240 последних точек `whiteScore` / `redScore`, нормированных
   на их ON-порог. Линия `y = 1` — порог включения. По графику видно, поднимается ли
   `score` при повторном ударе, пока лампа ещё горит.
5. **Вкладки**:
   - **Журнал** — все `HitEvent` текущей сессии + статус доставки из SQLite
     (`pending` / `sent` / `failed xN`);
   - **Диагностика** — `DiagnosticsSnapshot` (FPS, среднее/макс. время анализа,
     пропущенные кадры, ambiguous-кадры, латентность сохранения, экспозиция и ISO
     сенсора), текущие ROI, baseline, пороги из `LampConfig`, путь к CSV;
   - **Ошибки** — последние 50 сообщений из `session.errors`.

## Типовой сценарий проверки

1. Закрепить телефон так, чтобы обе лампы попали в кадр (штатив, подставка).
2. `Start` → дождаться превью.
3. Потянуть рамки WHITE и RED так, чтобы они закрыли соответствующие лампы.
4. `Калибровка (обе выключены)` — не трогать лампы, пока не появится сообщение
   «Калибровка завершена».
5. Удар по белой лампе → в «Журнале» появляется `#1 white`, `WHITE HITS` = 1.
6. Удар по красной, не дожидаясь, пока белая погаснет → `#2 red`, порядок сохраняется.
7. `Сеть: нет` → удар → событие получает статус `pending`. `Сеть: есть` →
   демо зовёт `deliverPending()`, статус меняется на `sent`.
8. `CSV: вкл` → снять серию вспышек → `CSV: выкл` → забрать файл из каталога
   (путь виден во вкладке «Диагностика») и прогнать через
   `DetectionSession.replayCsv` для подбора порогов без камеры.

## Где что лежит

```
example/lib/
├── main.dart                        // MaterialApp, тёмная тема
├── home_page.dart                   // DetectionSession + UI, кнопки, вкладки
└── widgets/
    ├── roi_editor.dart              // перетаскиваемые ROI поверх превью
    ├── score_chart.dart             // график whiteScore/redScore
    ├── event_log.dart               // журнал + статусы доставки
    └── diagnostics_panel.dart       // DiagnosticsSnapshot + пороги + baseline
```

`home_page.dart` — единственная точка, где собирается `DetectionSession`:
источник кадров, репозиторий, отправитель, настройки, CSV-рекордер. Всё остальное
получает готовую сессию через конструктор.

## Замечания по железу

- **`ResolutionPreset.medium` (720×480)** по умолчанию: ROI это позволяет, и анализ
  кадра успевает между 30 fps. Если `avgAnalysisMs > 8` во вкладке «Диагностика» —
  поднимите `subsampleStep` (например, с 4 до 6) или уменьшите ROI.
- **Автоэкспозиция** на части телефонов продолжает жить после `lockSettle`: следите
  за `sensorExposureTimeNs` и `sensorSensitivity`. Если они дрейфуют, `redScore`
  (абсолютный прирост яркости) может ползти вверх без всякой вспышки.
- **Панорамирование рукой** во время калибровки сдвигает baseline. Калибруйте только
  когда телефон зафиксирован.
