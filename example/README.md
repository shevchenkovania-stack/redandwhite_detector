# Демо `lamp_detection` на телефоне

Экран проверки детектора: живая камера, две рамки на колпаки, счётчик ударов и
всё, чем можно подтвердить или опровергнуть число. Алгоритм, числа и перенос в
другой проект описаны в [README пакета](../README.md) — здесь только экран и
как с него снимать данные.

## Запуск

```
flutter run -d <android-id>                    # с телефона по USB
flutter build apk --debug
adb install -r -d build\app\outputs\flutter-apk\app-debug.apk
adb shell monkey -p dev.lampdetection.lamp_detection_example -c android.intent.category.LAUNCHER 1
```

`-r -d` сохраняет `SharedPreferences` — рамки, калибровку, id сессии.
`flutter install` ставит с удалением, и всё это стирается (после него надо
заново навести рамки).

Сборка после `flutter clean` или `pub get` занимает около минуты: нативных
зависимостей в демо нет, свет меряет только ядро Dart на чистых числах кадра.

## Что на экране

| элемент | что делает | откуда |
|---|---|---|
| превью + две рамки | наведение на колпаки жестом; сохраняется в `lamp_detection.roi` | `RoiEditor` (`lib/widgets/roi_editor.dart`) |
| `Пуск` / `Стоп` | камера и обработка кадров | `session.start()` / `stop()` |
| `1 ФОН`, `2 БЕЛАЯ`, `3 КРАСНАЯ` | три состояния калибровки; в живом отсчёте не обязательны — это самопроверка «рамка видит лампу» | `session.calibrateStep(...)` |
| `БЕЛАЯ 0` `КРАСНАЯ 0` и ⟳ | счётчики ударов; ⟳ обнуляет счёт, не трогая калибровку | `session.whiteHits` / `redHits`, `resetCounters()` |
| полоса `ГОТОВ К РАБОТЕ` (или чего не хватает) | можно ли жать; не «жива ли программа» | `session.readiness` |
| `СВЕТ ЗАНОВО` прямо на полосе | перемерить свет заново, НЕ теряя счётчики. Нужно, когда наводил рамки при горящих лампах: «пол» набрался по засвету и канал залип | `session.relearnLight()` |
| плашки `РЕШЕНИЕ: ЯРКОСТЬ + ГЕОМЕТРИЯ`, `ЖИВОЙ ПОЛ` / `ЭТАЛОНЫ` | чем именно сейчас считаем; другого способа решения, кроме яркости четырёх областей, в коде нет | `session.config.liveReference` |
| `⋮` | 3 пункта: `Сброс калибровки` (убирает базу, собранный набор и «пол» живого отсчёта; счётчики ударов остаются — для них ⟳), `Журнал событий`, `Ошибки` | `session.resetCalibration` |

## Числа на экране и в логе

События считает только ядро Dart: яркость четырёх областей кадра, живой «пол»
и геометрия ореола. Другого способа измерения в демо нет.

CSV пишется всегда, без переключателя: путь печатается в `session.csvRecorder.filePath`
и в логе. `LAMPDBG` — тоже всегда.

## Порядок работы на стенде

1. `Пуск`, дождаться кадров.
2. Навести рамки так, чтобы в каждой был СВОЙ колпак (кольцо-ореол при этом
   залезает на чужую лампу — это нормально и учтено).
3. Лампы погашены → `СВЕТ ЗАНОВО` (или `Стоп` → `Пуск`).
4. Дождаться полосы `ГОТОВ К РАБОТЕ`.
5. Серия вспышек; сверять с эталонным счётчиком панели (`../sim_app`).

Калибровка — по желанию: три кнопки в том же порядке, при пересвете шага «фон»
демо само убавит экспозицию и наберёт шаг заново.

## Снятие чисел с телефона

```
adb logcat -s flutter:DartVm | Select-String "LAMPDBG|LAMPROI|PANEL"
adb exec-out screencap -p > screen.png
adb shell run-as dev.lampdetection.lamp_detection_example cat shared_prefs/FlutterSharedPreferences.xml
adb shell run-as dev.lampdetection.lamp_detection_example cat databases/lamp_events.db
```

Расшифровка полей `LAMPDBG live` — в [README пакета](../README.md), раздел
«Где смотреть числа».

## Чего демо честно не делает

- не определяет лампы само: рамки ставит человек, автопоиск удалён;
- не считает «физические» вспышки — считает подтверждённые переходы
  «погасла → горит», длинное горение = один удар;
- не отправляет события куда-либо: транспорт — `MockHitEventSender`;
- не подстраивается под чужой UI: всё состояние живёт в одном экране.
