# lamp_detection

Счётчик вспыхивающих сигнальных ламп (белая и красная) по камере Android.
Библиотека на Flutter: берёт кадры, решает «вспыхнула ли лампа и какая»,
превращает подтверждённую вспышку в `HitEvent`, кладёт его в SQLite и отдаёт
приложению на отправку. Транспорта в пакете нет — есть интерфейс.

Всё, что нужно понять про детекцию, занимает три предложения: **камера не
различает лампы, лампы различает рамка**; **вспышка — это подъём яркости над
«полом» из последних кадров, а не абсолютная яркость**; **удар — это подтверждённый
переход «погашена → горит», а не каждый кадр, где лампа горит**. Остальное —
защита от того, что кадр бывает враньём (пересвет, автоэкспозиция, ореол чужой
лампы, движение телефона).

## Три программы в этом репозитории

| | что это | детектит? |
|---|---|---|
| `lib/` | сам пакет `lamp_detection` | да, это и есть детектор |
| `example/` | демо на телефоне: камера, рамки, счётчики, меню | да, через пакет |
| `sim_app/` | панель на Windows: показывает «лампы» и считает эталон | **нет**, там нет ни одной строки детекции |

Эталон при сверке — счётчик панели, он независим от нашего кода. Если оба
«знают» про вспышку одно и то же, детекция верна.

## Алгоритм на каждом кадре

Путь одного кадра — сверху вниз, против него в логах пишут `LAMPDBG`.

| # | где | что делает |
|---|---|---|
| 1 | `camera/camera_frame_source.dart` | `camera` 0.12 отдаёт YUV-кадр; новый кадр приходит только когда предыдущий обработан. Отсюда же `buildPreview()` и захват экспозиции |
| 2 | `session/detection_session.dart` → `_onFrame` | один кадр = одна обработка; пока идёт обработка, следующие кадры считаются потерянными (`droppedFrames`) |
| 3 | `detection/feature_extractor.dart` | по двум рамкам (+ двум кольцам) считает признаки. Считает **только внутри рамок** — потому солнце, лампа потолка и блик от экрана в статистику не попадают |
| 4 | `detection/lamp_detector.dart` | решает по признакам: горит / погасла / ambiguous / ничем не объяснимо |
| 5 | `detection/live_reference.dart` | если режим живой (по умолчанию) — именно здесь берётся «пол» и подъём над ним |
| 6 | `detection/hit_state_machine.dart` | из «горит» делает событие: ровно одно на подтверждённое включение |
| 7 | `storage/sqlite_event_repository.dart` → `delivery/` | событие записано → отправлено → помечено; при старте доотправляются недоставанные |
| 8 | `diagnostics/feature_csv_recorder.dart` | покадровая строка в CSV (65 колонок) — чтобы прогон можно было разобрать и воспроизвести без телефона |

### Что именно измеряется в рамке (`FrameFeatures`)

| поле | как считается | зачем |
|---|---|---|
| `whiteFrac` | доля пикселей, где `min(R,G,B) ≥ whiteMinChannel` | «настоящий белый» |
| `redFrac` | доля пикселей, где `R − max(G,B) ≥ redMargin` и `R ≥ redMinValue` | «настоящий красная», тёмно-бордовые тени отсекаются |
| `meanY` | среднее Y (яркость) | замечает, что посветлела вся сцена = уехала автоэкспозиция |
| `p90Luma` | 90-й процентиль яркости (`lumaPercentile`) | «много ярко» против «средне»: один блик его не сдвигает, залитый колпак — сдвигает |
| `lumaStdDev` | разброс яркости | свет лампы ложится пятном, общее освещение поднимает область целиком |
| `clippedRatio` | доля пикселей ярче `clipLuma` (248) | качество кадра: на потолке сенсора ни цвета, ни запаса яркости нет |
| `sampleCount` | сколько пикселей реально попало в подвыборку | рамка может стоять на 3 пикселях — тогда ей нельзя верить |

Кольцо — та же рамка, расширенная в `ringScale` (1.7) раза: `whiteRing`,
`redRing`. Нужно потому, что **у настоящей лампы светит ореол, а колпак при
включении может даже побледнеть** (пересвет).

### Почему «какая лампа» решает рамка, а не цвет

Способ ровно один: событие принадлежит той лампе, в чьи рамки лёг подъём
яркости. Цвет как судья исключён намеренно: пересвеченная красная лампа для
сенсора белая, и при цветовом решении её вспышка уезжает в белую корзину — ровно
тот баг, который ловили руками. Цветовой ветки в коде больше нет, и переключать
на неё нечем. Цветные доли продолжают считаться и писаться в CSV — они нужны
для разбора записи, ни на одно решение они не влияют.

### Живой отсчёт — как устроен «пол» (`live_reference.dart`)

«Ноль» берётся из самих кадров, калибровка для работы не нужна.

1. По каждому признаку каждого канала держится окно последних
   `referenceWindowFrames` (20) кадров — примерно 2 секунды.
2. «Пол» = `referencePercentile` (20-й процентиль), а не среднее: вспышка داخل
   окна сдвинула бы среднее и вычла саму себя.
3. Шум окна = σ тех же кадров. Порог ON = `referenceNoiseSigmas` (6) × σ, но не
   ниже `referenceMinRise` (0.03) и не выше потолка `referenceMaxLevel` (0.15).
   Потолок критичен: у 6σ потолка нет, и когда окно описывает движение, а не
   темноту, порог становится 1.2–1.5 — до него вспышке не достать **никогда**.
   Уперлись в потолок = окно набирается заново.
4. Вспышка подняла канал → `rise = текущее − пол`. горит, если `rise > порога`.
5. **Общий свет вычитается.** `common = min(whiteRise, redRise)` — то, что
   поднялось на обеих рамках одинаково (вспышка, засветка, движение), —
   вычитается из обоих каналов перед решением «погасла ли». Иначе одна яркая
   вспышка задерживает второй канал в состоянии «горит» и весь прогон ложится в
   одну корзину.
6. **Кому принадлежит вспышка.** Если подъём на одной рамке ≥
   `LampCalibration.lampGateAsymmetry` (1.5) раза больше, чем на другой, тиший
   канал уступает — событие засчитывается громкому. Если обе рамки выросли и
   уступать некому, это **смена сцены**, а не удар: окно пересобирается, событие
   не создаётся.
7. Кольцо — усилитель СВОЕЙ лампы: оно не может решить за канал, если собственное
   ядро не шевельнулось (иначе ореол красной лампы, попадающий в белое кольцо,
   рисовал белые удары).

### Когда вспышка НЕ засчитывается

- после «Пуск» для каждой видимой зоны набираются 10 допустимых значений фона,
  а не 10 любых кадров (`liveWarmupLeft`; кадры с клиппингом не засчитываются).
  Пока фон не набран, `readiness` говорит «жду тёмный фон», а канал не считает;
- обе рамки выросли разом — смена сцены/освещения;
- подъём тише порога или не дотягивает до `referenceMinRise`;
- кадр на клиппинге (`overexposed`) — в таких пикселях информации нет;
- гашение не подтверждено. Подтверждение гашения живёт в `_LampTracker`
  (`lamp_detector.dart`) и требует **либо** провала к «полу», либо удержания
  ниже OFF-уровня дольше `offConfirmMs` (400 мс). Нужно именно «либо-либо»,
  потому что вспышка идёт волной: внутри одного горения амплитуда проваливается
  (замер — провал в 3 кадра, до ~300 мс), и правило только «по кадрам»
  взводилось заново и считало один удар дважды. `offConfirmMs` — единственное
  число в конфиге, выбранное между двумя измеренными границами, а не по гаданию;
  измерить его точнее должен `RunAnalyzer` на живой записи;
- `onConfirmFrames` (2) — короткие одиночные помехи, не успевшие подтвердиться.

### Режим эталонов (`liveReference: false`)

Старый путь, оставлен для сравнения. Калибровка снимает три состояния
(`CalibrationStep`: `background`, `whiteOn`, `redOn`), из них делаются шаблоны
«состояние − фон», а каждый кадр раскладывается на две амплитуды
(`response_model.dart`, `unmix`). ON = `max(hitFraction, 6 × шум амплитуды)`,
OFF = `offRatio × ON`. Отказ калибровки — самопроверка: если отклик лампы не
превышает шум фона в `templateMinSeparation` (6) раз, канал немой или рамка не
на том колпаке, и состояние не принимается. Сохранённый baseline верён только
при `currentVersion = 3` и трёх снятых состояниях, поэтому после смены формата
калибровку снимают заново; старше `baselineMaxAgeMinutes` (180) — не загружается.

### Экспозиция

`ExposureGuard` + захват AE/AWB в `CameraFrameSource`. Автоэкспозиция —
главный источник вранья: она поднимает и роняет всю сцену, а детектор принимает
это за вспышку. Признаки утечки — `exp=auto` в `LAMPDBG`, `exposureTimeNs` /
`sensorSensitivity` в CSV, доля клиппинга в кадре. При смене света, на котором
была набрана калибровка, калибровка сбрасывается автоматически
(`_onExposureBasisLost`).

## Все настраиваемые числа (`LampConfig`)

Значения по умолчанию — рабочие, стенд на них и считал. Реально настраиваемых
два: `hitFraction` и `offConfirmMs`. Остальные — измеренные константы, менять их
можно только имея замер, который это требует.

| число | по умолчанию | что значит |
|---|---|---|
| `liveReference` | `true` | считать от живого «пола», а не от сохранённой калибровки |
| `referenceWindowFrames` | 20 | глубина окна «пола», ~2 с |
| `referencePercentile` | 0.2 | какой процентиль окна считать полом |
| `referenceNoiseSigmas` | 6 | во сколько σ подъём должен быть вспышкой |
| `referenceMinRise` | 0.03 | абсолютный минимум подъёма (на ровной сцене σ = 0) |
| `referenceMaxLevel` | 0.15 | потолок порога ON; уперлись — окно не про темноту, пересобираем |
| `ringScale` | 1.7 | во сколько раз расширять рамку для кольца; 1.0 = колец нет |
| `lumaPercentile` | 0.9 | какой процентиль яркости брать по области |
| `clipLuma` | 248 | с какой яркости пиксель считается пересвеченным |
| `offRatio` | 0.6 | OFF-порог как доля ON-порога (гистерезис) |
| `onConfirmFrames` | 2 | кадров подряд выше ON, чтобы подтвердить включение |
| `offConfirmFrames` | 3 | кадров ниже OFF (нижняя граница; длительность задаёт `offConfirmMs`) |
| `offConfirmMs` | 400 | как долго обязан держаться провал, чтобы гашение считалось |
| `hitFraction` | 0.6 | доля измеренного отклика, при которой лампа «горит» (режим эталонов) |
| `templateMinSeparation` | 6 | во сколько раз отклик лампы должен превышать шум, иначе калибровка отвергается |
| `calibrationFrames` | 30 | пикселей на каждый шаг калибровки |
| `calibrationMaxNoise` | 0.03 | допустимая σ шага «фон» |
| `calibrationNoiseRatio` | 0.35 | какую долю собственного отклика разрешено занимать шуму на шаге горящей лампы |
| `baselineMaxAgeMinutes` | 180 | старше — калибровка не загружается |
| `subsampleStep` | 2 | каждый N-й пиксель по x и y |
| `analysisIsolateThresholdMs` | 8 | выше — анализ слишком медленный для этого устройства (флаг `needsIsolate`, изолята нет) |
| `yuvFullRange` | `true` | full range Y; иначе studio 16..235 растягивается в 0..255 |
| `whiteMinChannel` / `redMargin` / `redMinValue` | 170 / 60 / 110 | определения «белый пиксель» и «красный пиксель» |
| `scoreHistoryPoints` / `csvFlushLines` | 240 / 30 | размер буферов UI и CSV |

## Публичный API и быстрый старт

Импортировать можно только `package:lamp_detection/lamp_detection.dart`;
`src/**` — внутренность пакета. Отсчёт «пола» (`LiveReference` в
`detection/live_reference.dart`) наружу не вынесен намеренно: им пользуется
только `LampDetector`, и поменять способ отсчёта, не трогая приложение, — это
причина, по которой он внутренний.

| слой | классы |
|---|---|
| модель | `LampConfig`, `LampRoi`, `RoiLayout`, `FrameMapping`, `FrameFeatures`, `LampFrame`, `CalibrationState`, `LampBaseline`, `HitEvent`, `HitColor` |
| детекция | `FeatureExtractor`, `LampDetector`, `LampEvaluation`, `HitStateMachine`, `LampResponseModel`, `LampVector` |
| калибровка | `LampCalibration`, `CalibrationStep`, `CalibrationProgress`, `CalibrationReport`, `CalibrationException`, `ExposureGuard` |
| камера | `FrameSource`, `RawLampFrame`, `CameraFrameSource`, `CameraSourceOptions`, `LampCameraPreview` |
| хранилище | `EventRepository`, `SqliteEventRepository`, `StoredEvent`, `DeliveryStatus`, `lampDataDirectory()` |
| доставка | `HitEventSender`, `DeliveryResult`, `MockHitEventSender` |
| диагностика | `DiagnosticsCollector`, `DiagnosticsSnapshot`, `FeatureCsvRecorder`, `FeatureCsv`, `RunAnalyzer`, `RunAnalysis`, `DarkRunTiming` |
| фасад | `DetectionSession`, `LampStatus`, `SettingsStore` |

`DetectionSession` — единственная точка входа для приложения: он склеивает
источник кадров, экстрактор, детектор, автомат, хранилище, доставку и диагностику,
и он же `ChangeNotifier`.

```dart
import 'package:lamp_detection/lamp_detection.dart';

final directory = await lampDataDirectory();          // приватный каталог БД sqflite
final session = DetectionSession(
  source: CameraFrameSource(),
  repository: SqliteEventRepository(
    fileName: SqliteEventRepository.defaultFileName,
    directory: directory.path,
  ),
  sender: MockHitEventSender(),                       // сюда — свой транспорт
  settings: await SettingsStore.open(),
  csvRecorder: FeatureCsvRecorder(directory: directory),
);

await session.loadSettings();                         // ROI, конфиг, калибровка, id сессии
session.addListener(() {/* session.status, session.readiness */});
session.hits.listen((HitEvent e) {/* новое событие */});
session.errors.listen((String m) {/* камера и обработка не падают — всё сюда */});
await session.start();                                // включает камеру и доотправляет долг
```

Экрану остаются: `source.buildPreview()` как превью, наложение двух рамок,
`session.updateRoi(layout, persist: true)` после наводки, `session.stop()` и
`session.dispose()` при выходе.

## Как перенести функционал в другой проект

1. **Зависимость.** Локально — `path:`:

   ```yaml
   dependencies:
     lamp_detection:
       path: ../lamp_detection
   ```

   Транзитивно придут `camera`, `shared_preferences`, `sqflite`, `uuid`, `path` —
   объявлять их в своём `pubspec.yaml` не нужно, если только вы не пользуетесь
   ими напрямую.

2. **Проверьте версию SDK.** Пакет требует `environment: sdk: ^3.11.1`. Если в
   принимающем проекте Flutter старше — либо обновляйте его, либо скажите, и я
   опущу границу до версии, которая у вас (языковых фич новее 3.10 в `lib/` нет,
   но границу надо подтвердить сборкой).

3. **Платформа.** Рассчитана на телефон с камерой: Android проверен живым
   устройством, iOS поддержан в коде, но на железе не запускался.
   Разделение платформ вшито: `_defaultFormatGroup()` даёт Android `yuv420`,
   а iOS `bgra8888`, и `FeatureExtractor` для BGRA имеет отдельный источник
   (`_BgraSource`) — то есть путь iOS написан явно, а не «авось прокатит».
   Что остаётся проверить на живом iPhone:
   * соответствие превью↔кадр: формула `sensorOrientation/90` выведена по
     Pixel 8 Pro, на iOS плагин доворачивает превью по ориентации интерфейса.
     Симптом промаха — рамки «не попадают», хотя нарисованы верно; лечится на
     месте: `session.setFrameMapping(1 | 3, mirror: ...)`;
   * ориентацию интерфейса надо зафиксировать самому (`SystemChrome
     .setPreferredOrientations`) — в пакете и в демо этого нет, а на iOS при
     перевороте телефона ROI поедут;
   * `yuvFullRange` на iOS не при чём — там RGB-путь.

   Windows и web под `lamp_detection` не предназначены: там нечего показывать
   камере. Для iOS — `NSCameraUsageDescription` в `Info.plist` (в демо он есть),
   без него приложение падает молча.

4. **Разрешения.** В `android/app/src/main/AndroidManifest.xml`:

   ```xml
   <uses-permission android:name="android.permission.CAMERA"/>
   <uses-feature android:name="android.hardware.camera" android:required="true"/>
   ```

   Плюс запрос разрешения на рантайме (`permission_handler` или
   `Camera.requestPermissions`); само по себе объявление ничего не даёт.

5. **Инициализация.** До создания сессии обязателен
   `WidgetsFlutterBinding.ensureInitialized()` — нужен `SharedPreferences`
   (`SettingsStore.open()`) и `sqflite`. На десктопе дополнительно понадобился бы
   `sqflite_common_ffi`, но он в `dev_dependencies` пакета и приложению на
   телефоне не нужен.

6. **Своё вместо заглушки.** Реализуйте `HitEventSender`:

   ```dart
   class MyApiSender implements HitEventSender {
     @override
     Future<DeliveryResult> send(HitEvent event) async {
       try {
         await http.post(/* event.toJson() */);
         return const DeliveryResult.success();
       } on Object catch (e) {
         return DeliveryResult.failure('$e');   // событие останется pending
       }
     }
   }
   ```

   Очередь и защита от дублей уже в `SqliteEventRepository` (`eventId` уникален,
   статусы `pending`/`sent`/`failed`), повтор — `session.deliverPending()`
   (сам вызывается при `start()`). Периодического фонового повтора нет — зовите
   `deliverPending()` по своему таймеру или по событию сети.

7. **Рамки.** `LampRoi(left:, top:, width:, height:)` — доли кадра 0..1, минимум
   0.02 по стороне. Задать можно и без UI:
   `session.updateRoi(const RoiLayout(white: LampRoi(...), red: LampRoi(...)), persist: true)`.

8. **Ориентация сенсора.** Если рамки «не попадают» на лампы при верно нарисованном
   оверлее — это не наводка, это соответствие превью↔кадр:
   `session.setFrameMapping(quarterTurns, mirror: ...)`. Формула считается из
   `sensorOrientation`, но на конкретном устройстве может не угадать; перебор
   в 4 значения — штатная проверка.

9. **Что брать из `example/`, если нужно то же поведение экрана:**

   | файл | строк | брать? |
   |---|---|---|
   | `example/lib/widgets/roi_editor.dart` | 213 | **да, копировать** — редактора рамок в пакет сознательно не положен (это UI вашего приложения) |
   | `example/lib/home_page.dart` | 1095 | как образец порядка вызовов; целиком не тащить |
   | `example/lib/widgets/event_log.dart` | 52 | по вкусу |

10. **Минимальный чек-лист переноса:** зависимость → разрешения →
    `ensureInitialized` → собрать сессию как в быстром старте → превью +
    наведение 2 рамок → `start()` → слушать `hits` → свой `HitEventSender` →
    `stop()`/`dispose()`. Детекцию настраивать нечем: `LampConfig()` по умолчанию
    и есть стендовый режим.

## Известные ограничения (проверены по коду, не «на глаз»)

- **Метки времени кадра нет.** `camera` 0.12 не отдаёт timestamp экспозиции,
  поэтому `LampFrame.timestamp` = `DateTime.now()` в колбэке плагина. Внутри
  устройства стабильно, с сервером по UTC не синхронизировано.
- **Изолята нет.** `needsIsolate` — только флаг. Если анализ медленный:
  больше `subsampleStep` или ниже `resolutionPreset`.
- **Односторонний скачок фона** в живом отсчёте (поднялась одна рамка) неотличим
  от вспышки — одно ложное событие на самом переходе. Обе рамки разом — это
  смена сцены, не считается. Лечится «Пуск» (окно наберётся заново), кнопкой
  `СВЕТ ЗАНОВО` или перекалибровкой.
- **Панорамирование рукой** сдвигает признаки внутри ROI и может как занижать,
  так и ложно поднимать отклик: всё настроено под статив/закреплённый телефон.
- **Реальная частота обработки не измерена на стенде.** От неё напрямую
  зависит, дойдёт ли короткая вспышка до `onConfirmFrames`.
- **Точность детекции не подтверждена после правки корзины** — приёмочный прогон
  «3 белых / 3 красных» с раздельными корзинами ещё не делался, `offConfirmMs`
  остаётся расчётным, а не измеренным.

## Частые вопросы: где смотреть

| симптом | куда смотреть, по коду |
|---|---|
| «ничего не считает» | `session.readiness` (что именно не хватает), `liveWarmupLeft`, `exp=lock\|auto` в `LAMPDBG` — автоэкспозиция глотает подъём |
| «рамки не попадают на лампы, хотя нарисованы верно» | это не наводка, а превью↔кадр: `LAMPROI` (где рамка в пикселях) и `session.setFrameMapping(...)` |
| «все удары в одну корзину» | `nW`/`nR` в `LAMPDBG` (подъёмы после вычитания общего света) и `hits W R`; если оба подъёма равны, асимметрии для гейта нет — виноват свет, а не автомат |
| «один удар считается дважды» | провал внутри горения короче `offConfirmMs`: `suggestedOffConfirmMs` у `RunAnalysis` на CSV прогона |
| «канал прилип к „горит“» | окно набралось не по темноте: `СВЕТ ЗАНОВО` (или «Пуск»), потолок `referenceMaxLevel` |
| «после обновления всё молчит» | `LampBaseline.currentVersion` и `baselineMaxAgeMinutes`: старая калибровка отвергается при загрузке, нужно снять заново |
| «камера стартует вечность» | плагин `camera` на части устройств не отвечает вовсе: через 25 с экран сам пишет причину — это не сборка |

## Демо, панель, тесты

```
cd example  && flutter run -d <android-id>        # телефон
cd example  && flutter build apk --debug && adb install -r -d build\app\outputs\flutter-apk\app-debug.apk
cd sim_app  && flutter run -d windows             # панель с эталонным счётчиком
flutter analyze --no-pub                          # пакет и example
```

`-r -d` при установке сохраняет `SharedPreferences` (рамки, калибровку) —
`flutter install` ставит с удалением и всё это стирает.

Порядок работы на стенде: Пуск → навести рамки на колпаки → (лампы погашены)
`СВЕТ ЗАНОВО` или Пуск повторно → дождаться полосы `ГОТОВ К РАБОТЕ` → серия
вспышек. Калибровка (`1 ФОН` / `2 БЕЛАЯ` / `3 КРАСНАЯ`) живому отсчёту не
обязательна — она самопроверка «рамка видит лампу».

Тесты (`test/`, 63 штуки, все проходят) — синтетические сцены на тех же
величинах, что даёт живая камера: `support/synthetic_scene.dart`,
`support/session_fakes.dart`. Покрыты расклад на эталоны, живой «пол»,
решение по яркости четырёх областей, разделение корзин, автомат попаданий,
basis измерения и `RunAnalyzer`.

Хроника того, что получалось и что не проверено, — [`docs/ЖУРНАЛ.md`](docs/ЖУРНАЛ.md);
краткая история изменений по версиям — [`CHANGELOG.md`](CHANGELOG.md).
